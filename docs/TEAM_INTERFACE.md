# 三组接口与协作约定

> 参与方：界面组（UI）/ 搭桥组（Bridge）/ 逻辑组（Engine，L1 战斗线 + L2 驱动线）
> 状态：草案 v0.1 —— 第 1 周内三组逐条确认后冻结 v1.0
> 相关文档：[engine/CONTRACT.md](../engine/CONTRACT.md)（引擎内部契约）、`PROTOCOL.md`（搭桥组产出的报文格式，以本文件 B 组条目为准）

**为什么需要这份文档**：大纲第 4 节只定了「传什么消息」，没定「进程怎么起、日志往哪打、坐标原点在哪、谁判合法性」。这四件事没定，第 3 周联调会以「三组互相认为对方写错了」告终。

## 1. 逻辑组 ↔ 搭桥组（进程边界）

| # | 约定 | 约定值 | 责任方 | 桥 | 引擎 |
|---|---|---|---|---|---|
| B1 | **拉起命令** | `python -m engine.main --stdio`；工作目录=项目根；环境带 `PYTHONUNBUFFERED=1`（或 `-u`）；`--headless` 为纯命令行模式，不读 stdin 协议 | 桥接组实现，逻辑组提供入口 | ☐ | ☐ |
| B2 | **握手** | UI 发 `HELLO` → 引擎回 `HELLO_ACK{protocol_version: int}`；**2 秒**无 ACK 判「引擎未启动」；版本不一致立即报错并提示 | 双方 | ☐ | ☐ |
| B3 | **stdout 独占** | 引擎 stdout **只允许协议 JSON 行**；日志/调试走 stderr 或 `--log FILE`；桥接层必须 `setProcessChannelMode(SeparateChannels)` 把 stderr 单独接出。此条必须写进 PROTOCOL.md | 逻辑组保证，桥接组依赖 | ☐ | ☐ |
| B4 | **行协议细节** | UTF-8（无 BOM）、一行一条 JSON、`\n` 结尾、**禁止 `\r`**；**单行上限 64KB**；界面用 `readLine()` 逐行读 | 双方 | ☐ | ☐ |
| B5 | **快照频率与丢帧** | 引擎固定 30 行/秒；**允许界面丢帧**（只取最新一帧）；不允许引擎按界面节奏降频 | 逻辑组产出，界面组消费 | ☐ | ☐ |
| B6 | **正常退出** | 收 `exit` → 回 `BYE` → 退出码 0；界面关窗（关 stdin）→ 引擎读到 EOF 自行退出（≤1 秒）；桥接层再兜底 `terminate/waitForFinished` | 双方，各自兜底 | ☐ | ☐ |
| B7 | **崩溃上报** | 引擎顶层捕获异常 → 输出 `{"type":"engine_error","msg":"..."}` 一行 → 退出码 1；桥接组据此提示「引擎已退出」并允许重开 | 双方 | ☐ | ☐ |
| B8 | **建塔失败的回法** | 不阻塞、不重试：以 `{"type":"info","code":"too_poor|occupied|blocked|no_tower|max_level|bad_command","cell":[...]}` 回传。**这是事件，不是应答**，桥接层不得同步等待 | 逻辑组产出，界面组展示 | ☐ | ☐ |
| B9 | **map / config 下发时机** | 仅 `start` 之后发一次；再次 `start` 视为重开一局：重发 `map`/`config`，world 重置、实体 ID 归零、**不重启进程** | 逻辑组 | ☐ | ☐ |
| B10 | **协议签字** | 逻辑组在第 1 周内完成 PROTOCOL.md 字段 review 并签字；未冻结前不写依赖对方的代码 | 逻辑组 | ☐ | ☐ |

**引擎侧需要桥接组明确回答的两个问题**

1. Qt 用 `QProcess` 时，stderr 是否单独接出来（`setProcessChannelMode(SeparateChannels)`）？若与 stdout 混流，引擎的日志会污染协议解析 —— 必须分开。
2. 引擎已被 `terminate()` 但仍未退出时，等待多久后 `kill()`？（建议 1 秒）

## 2. 逻辑组 ↔ 界面组（数据含义）

| # | 约定 | 约定值 | 责任方 | UI | 引擎 |
|---|---|---|---|---|---|
| U1 | **坐标语义**（最高优先） | 格子 `(x, y)`：原点**左上角**、x 向右、y 向下、**从 0 开始**；引擎下发的 `x/y` 是**格子中心**浮点。像素换算只写在界面一个函数里 | 三方签字 | ☐ | ☐ |
| U2 | **图标来源** | 配置只给逻辑键 `type` + `name` + `icon`（字符串键），**不给图片路径**；界面自己维护 key→资源映射。缺资源时画色块 | 界面组 | ☐ | ☐ |
| U3 | **合法性判定归属** | 界面只上报「点了哪个格子 + 选了哪种塔」，是否可建、金币够不够由引擎判；界面依据 `info` 事件给红框/提示 | 引擎判，界面展示 | ☐ | ☐ |
| U4 | **界面不自己累计** | 金币/血量/波次/分数一律以 `state` 与 `result` 事件为准，界面不做增减，避免两套状态机 | 界面组遵守 | ☐ | ☐ |
| U5 | **结算数据来源** | `result` 事件带 `win / kills / leaks / gold_left / hp_left / duration_ticks`，结算页直接显示，不二次统计 | 逻辑组产出 | ☐ | ☐ |
| U6 | **不等待回执** | `place_tower / upgrade_tower / sell_tower / set_speed` 全异步，界面点完立即返回，不等 ack、不阻塞 UI | 界面组 | ☐ | ☐ |
| U7 | **重开一局** | 再发 `start{level_id}` 即可，不销毁子进程；界面需清空上一局画面与本地缓存 | 双方 | ☐ | ☐ |

**必须同时写进界面侧的换算公式**（避免各写一套）：

```
pixel = grid_origin + (grid_x * cell_size, grid_y * cell_size)   # grid_x/y 为格子中心坐标
点击反算：grid_x = (pixel_x - grid_origin_x) / cell_size 后 int() 取整
```

## 3. 三方共同

| # | 约定 | 约定值 | 责任方 |
|---|---|---|---|
| C1 | **环境统一** | Python 版本、Qt/Creator 版本写进 README，三组一致（大纲第七节） | 搭桥组汇总 |
| C2 | **一键启动** | 界面组点「运行」即可拉起引擎，无需手动开终端；由搭桥组交付 | 搭桥组 |
| C3 | **模拟引擎** | 搭桥组提供按行吐假 JSON 的模拟引擎，界面组在真引擎就绪前用它开发 | 搭桥组 |
| C4 | **联调窗口** | 第 3 周起每天固定一段全员在线的联调时段；联调问题当场记录、当天分派 | 三方 |
| C5 | **问题定位材料** | 联调出问题时，逻辑组提供引擎侧 `--log` 日志（含 tick 号），界面组提供收到的原始行；双方对同一 tick 交叉比对 | 三方 |

## 4. 冻结与变更

1. 三组各自 review 本文件与 PROTOCOL.md，逐条打勾；全部打勾即冻结 v1.0。
2. 冻结后新增字段：发起方在群里提出 → 受影响组确认 → 改 PROTOCOL.md 与 [engine/CONTRACT.md](../engine/CONTRACT.md) §3 → 当天同步实现。
3. **禁止**「先改自己那边，让对方适配」。字段名、坐标语义、退出语义三者变更必须三方同时确认。

## 5. 第 3 周联调检查清单

按顺序过，每条都能在 1 分钟内验完：

- [ ] 点「运行」→ 引擎进程起来，2 秒内收到 `HELLO_ACK`（B1/B2）
- [ ] 引擎 stdout 里**没有**任何非 JSON 行；故意触发一次配置错误，日志出现在 stderr（B3）
- [ ] 开局收到 `map` + `config`，地图画出后塔位与路径点对得上，**不差半格**（U1）
- [ ] 建塔成功后 `state.towers` 出现该塔；建在路上/金币不足时收到 `info` 且界面提示（U3/B8）
- [ ] 敌人从起点走到终点，位置与路径折线一致，不漏怪时血量不变（U1）
- [ ] 漏一只怪 → `leak` 事件 + 血量下降，界面显示值与 `state.hp` 一致（U4）
- [ ] 击杀 → `gold` 变化，界面金币不出现「跳回旧值」（D10 顺序）
- [ ] 暂停后 `tick` 不再增长，但点建塔仍生效（I5）
- [ ] 倍速 2/3 下画面流畅，无穿怪、无跳帧错位（B5）
- [ ] 关闭窗口 → 进程列表里 Python 子进程消失（B6）
- [ ] 手动 kill 引擎 → 界面提示「引擎已退出」且能重开（B7）
- [ ] 点「再玩一局」→ 不重启进程，金币/血量/塔全部复位（B9/U7）
