## 一、我们要做什么

一个桌面塔防游戏：Qt 做界面，Python 做游戏逻辑，中间用一层桥接把两边连起来。

玩法定为固定路径塔防（保卫萝卜式）：敌人沿一条固定路线从起点走到终点，我们在路边建塔攻击它；塔和敌人不会碰撞、不会互相阻挡。这是塔防里最好实现的一类，目前工期集中在"做完"而不是"做复杂"。

先跑通最小闭环：1 张地图、2 种塔、2 种敌人、3 波。跑通之后再靠改配置文件加内容，不改代码。

## 二、三层架构（先记住这张图）

```text
界面组 → UI 层（C++ Qt 窗口、地图、按钮、金币血量显示）
             ↕
        桥接层（Qt 拉起 Python 子进程，按行传 JSON）
             ↕
逻辑组 → 引擎层（Python 子进程：敌人怎么走、塔怎么打、波次怎么刷）
```

一句话：界面组和逻辑组不直接打交道，都通过桥接层传消息。桥接层由搭桥组负责。

方式暂定：界面启动时由 Qt 拉起一个 Python 子进程，界面往它的 stdin 写指令、从它的 stdout 读状态，每行一条 JSON。不用网络、不用端口、不用处理粘包。

## 三、三组分工

| 组别 | 你负责 | 你的交付物 | 你不用管 |
|---|---|---|---|
| 界面组 | 所有 Qt 界面：主菜单、游戏画面、塔选择栏、金币血量栏、结算页 | 用假数据能把"菜单→游戏→结算"整个界面流程走通 | 塔怎么攻击、敌人怎么走、网络细节 |
| 搭桥组 | 通信协议文档、QProcess 子进程封装、按行 JSON 编解码、子进程管理、一键启动 | 界面能拉起 Python 引擎并互通一条消息（握手） | 游戏玩法、界面长什么样 |
| 逻辑组 | 所有游戏逻辑和配置文件：地图、敌人、塔、子弹、波次 | 命令行里不开界面能跑完 3 波，并打印通关/失败结果 | 界面控件、网络帧格式 |

## 四、接口契约（都要看，这是最容易出事的地方）

界面和引擎之间只传 JSON 消息，每行一条、以换行结束（按行读，不会粘包）。字段先按下面来，改动必须三组一起确认。Python 输出每一行都要加 `flush=True`，否则状态会卡在缓冲区送不出来——这是唯一要特别小心的地方。

### 4.1 界面发给引擎（指令）

| 消息 | 带什么 | 什么时候发 |
|---|---|---|
| 开始游戏 | 关卡编号 | 点"开始"按钮 |
| 建塔 | 塔类型、格子坐标 | 在地图上点空地 |
| 升级 / 出售 | 塔编号 | 点已有的塔 |
| 下一波 | 波次编号 | 点"开始下一波" |
| 倍速 / 暂停 / 继续 | 倍速值或空 | 点对应按钮 |
| 退出 | 无 | 关闭游戏 |

### 4.2 引擎发给界面（状态和事件）

| 消息 | 带什么 | 什么时候发 |
|---|---|---|
| 地图 | 格子、路径点、起点终点 | 开局发一次 |
| 每帧状态 | 金币、血量、波次、所有塔/敌人/子弹的位置和血量 | 每秒约 30 次 |
| 配置 | 塔和敌人的名字、价格、图标 | 开局发一次 |
| 击杀 / 漏怪 / 波次 / 结算 | 加分、扣血、波次号、胜负 | 事件发生时 |

### 4.3 四条硬约定

- 坐标：都由引擎用格子坐标算好，界面只负责换算成屏幕像素，换算只写在一个函数里。
- 帧率：引擎每秒推进 30 步，界面每 30 毫秒取最新一帧来画，不要每收到一帧就画一次（会卡）。
- 按行 + flush：每行一条 JSON；Python 输出必须 `print(..., flush=True)`，界面用 `readLine()` 逐行读。
- 进程管理：界面关掉时要主动结束 Python 子进程；子进程崩溃要能提示「引擎已退出」并允许重开。

## 五、每人第一步做什么

### 5.1 界面组

1. 装好 Qt Creator，新建 Qt Widgets 工程。
2. 先把四个页面空壳搭出来：菜单、游戏、结算、塔选择栏。
3. 用假数据（搭桥组会提供一个模拟服务）把整个界面流程走通，先不接真引擎。
4. 地图用 `QGraphicsView` 画，塔和敌人用色块或简单图形代替即可。

### 5.2 搭桥组

1. 第一件事：把第 4 节的消息写成一份协议文档（`PROTOCOL.md`），三组确认后冻结。
2. 用 `QProcess` 写子进程封装 + 按行 JSON 收发，先跑通握手（界面发 `HELLO`、引擎回 `HELLO_ACK`）。
3. 处理子进程启动/退出、崩溃提示，界面关掉时回收子进程。
4. 做一个模拟引擎（同样按行吐假 JSON），让界面组在没有引擎时也能开发。

### 5.3 逻辑组

1. 建 Python 虚拟环境，只用标准库（`sys`、`json` 都是自带）。
2. 先写不依赖界面的主循环：敌人沿路径走、塔在射程内攻击、子弹扣血、波次刷怪。
3. 数值全部写进配置文件（塔、敌人、波次、地图各一个文件）。
4. 命令行跑完 3 波，打印结果就算这一阶段达标。

## 六、时间线

| 周次 | 目标 | 本周结束时要看到什么 |
|---|---|---|
| 第 1 周 | 定协议、搭骨架 | 协议文档冻结；三组各自跑通最小示例 |
| 第 2 周 | 各做各的核心 | 逻辑能跑完 3 波；界面能用假数据走通全流程 |
| 第 3 周 | 联调 | 真界面 + 真引擎跑通完整一局，修掉不同步和坐标错位 |
| 第 4 周 | 扩展和收尾 | 加塔加敌、打磨点击反馈、写说明文档，可演示 |

## 七、协作规则（必守）

1. 先定协议再写码：协议没冻结前，别写依赖对方的代码。
2. 每天合并一次：各人在自己的分支开发，每天合并到主分支，冲突当天解决。
3. 数值进配置：塔、敌人、波次的数值都放配置文件，加内容只改文件不改代码。
4. 环境统一：Qt 版本、Python 版本三组保持一致，写进说明文档。
5. 图片先不用管：第一版用色块和简单图形就行，等游戏跑通了再考虑美术。别一开始就找素材，会拖慢进度。
